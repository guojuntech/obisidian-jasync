# JASync 0.2.8

补充 S3 同步诊断，帮助定位 Android 的 `S3 delete capability check failed: S3 network request failed`。本次发布增加错误细节，不宣称已修复尚未在 Android 实机定位的网络问题。

- 能力探测记录请求方法、创建/覆盖/删除类型、具体步骤、耗时和请求关联 ID。
- 正常响应保留 HTTP 状态、S3/COS Code 和 RequestId；原生异常保留脱敏后的名称、消息、code、异常自报状态和有限的原因链。
- 区分超时、HTTP 错误、原生请求失败及清理失败。失败提示也包含请求方法和探测步骤。
- 导出增加平台、Obsidian API 版本和旧日志丢弃数量；内存最多保留最近 2000 条。
- 新增诊断不记录密钥、令牌、Authorization、完整 URL 或请求/响应正文。同步确认、条件写删、备份、取消和重试规则保持原有行为。

## Android 查看方法

更新并重新启用插件，复现报错后进入 **设置 → JASync → 排障 → 控制台日志 → 保存到笔记**。在 `jasync/logs/` 下的日志笔记中搜索 `[S3]`，查看 `method`、`capability`、`step`、`httpStatus`、`serviceCode`、`requestId` 和 `nativeError`。请在重启或禁用插件前导出。

例如 `delete/verify-deleted` 表示删除后的 HEAD 检查失败，不等于 DELETE 请求被拒绝。异常自报的 `reportedStatus` 与正常响应的 `httpStatus` 分开记录。详见 [S3 诊断指南](https://github.com/guojuntech/obisidian-jasync/blob/0.2.8/docs/S3-DIAGNOSTICS.md)。

验证：69 个单元测试文件 / 844 项测试、18 项原生 Obsidian 检查、ESLint、TypeScript、生产构建及 ZIP 内容校验通过；包含生产插件实际导出日志笔记和无 Node 全局对象环境的回归验证。Android 实机复现仍待用户验证。

## 安装与更新

BRAT 用户可从 `guojuntech/obisidian-jasync` 更新到 **0.2.8**。手动更新时先禁用 JASync，将 `jasync-0.2.8.zip` 中的插件文件覆盖到 `.obsidian/plugins/jasync/`，然后重新启用。保留本设备的 `data.json`、`data.local.json`、cache 和 recovery，无需重新配置或清除同步记录。

Release 包含 BRAT 使用的 `main.js`、`manifest.json`、`styles.css`，以及安装 ZIP、LICENSE、NOTICE.md 和 SHA256SUMS。最低 Obsidian 版本为 1.7.2。
