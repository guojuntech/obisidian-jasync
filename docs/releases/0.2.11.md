# JASync 0.2.11

修复 Android 上普通文件检查因 `HEAD ... Request Failed. IOException Stream closed` 中断同步的问题。

- 继续优先使用标准 HEAD。只有 Android 原生 requestUrl 在返回响应前抛出这一特定异常时，才对同一个对象重新签名，发送 `GET Range: bytes=0-0`。
- GET 404 按不存在处理，并保留虚拟目录检查；403 等权限或签名错误仍然失败，不会被误判为文件不存在。
- GET 206 校验范围和实际字节数，使用 Content-Range 的完整对象大小及最新 ETag；GET 416 再发一次 HEAD 检查空文件，避免循环补查。
- 服务端忽略 Range 返回 200 时，校验完整响应再使用元数据。这种情况下可能下载整个对象。
- 远端发生变化仍会阻止旧同步计划执行；条件写入和删除保护保持生效。
- 日志通过 `parentDiagnosticId`、`fallbackReason`、`fallbackStep` 串联原 HEAD 与补查。开启 Verbose log 可查看补查实际返回的 HTTP 状态、S3/COS 错误码、脱敏 Message 和 RequestId。不会把 GET 的状态伪装成原 HEAD 的状态。

这项兼容处理自动启用，不依赖 Verbose log 开关。Obsidian Android 1.13.8 的原生实现会在读取 HEAD 错误响应的空流时抛错，从而丢失已读取的 HTTP 状态；本版在插件侧补查当前对象状态。

## 更新

通过 BRAT 更新 `guojuntech/obisidian-jasync` 到 **0.2.11**，或安装 `jasync-0.2.11.zip`，保留原有配置、cache 和 recovery。复测时建议开启 **设置 → JASync → 排障 → Verbose log**，同步后及时保存日志到笔记。

验证：71 个单元测试文件 / 903 项测试、19 项原生桌面 Obsidian 检查、真实 COS 的 7 个场景、ESLint、TypeScript、生产构建和 ZIP 五文件内容校验均通过。Android 原生失败边界采用模拟，尚未在 Android 真机上验收。详见 [S3 诊断指南](https://github.com/guojuntech/obisidian-jasync/blob/0.2.11/docs/S3-DIAGNOSTICS.md)。
