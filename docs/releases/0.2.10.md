# JASync 0.2.10

新增可选的详细 S3 日志，帮助定位 Android 上 `HEAD ... IOException Stream closed` 的实际失败阶段。

在 **设置 → JASync → 排障 → Verbose log（S3 详细日志）** 开启，默认关闭，仅在当前设备保存。无需重启，现有会话中的后续请求也会生效。

- 覆盖每次 ListObjectsV2、HeadObject、GetObject、PutObject、DeleteObject，包括成功请求和普通文件请求。
- 记录 API、方法、URL、对象路径、查询参数、签名范围、脱敏请求/响应头、请求与响应字节数、毫秒时间、耗时、调用栈、重试次数和等待时间。
- 使用同一个 diagnosticId 串联请求。原生阶段分别标出 requestUrl 调用、读取响应状态/头、读取 arrayBuffer 的开始、完成与失败。
- 已交付的 HTTP 状态、COS/S3 错误码、RequestId 和脱敏错误 Message 会保留；requestUrl 未返回响应时，不虚构 HTTP 错误码。
- 凭据、签名、Cookie 和未知头值脱敏，笔记及列表正文省略。日志会包含 Bucket、Prefix 和文件名；字段限长，仍只保留最近 2000 条。

普通文件 stat 继续使用 HEAD。本版增加诊断信息，不改变请求、签名、条件保护或重试策略，也不宣称已修复 Android 原生网络异常。

## 更新与复现

BRAT 更新 `guojuntech/obisidian-jasync` 到 **0.2.10**；手动更新可使用 `jasync-0.2.10.zip`，保留原有配置、cache 和 recovery。

开启 Verbose log → 清空旧日志 → 同步复现一次 → 在重启或禁用插件前点击 **控制台日志 → 保存到笔记**。导出的 `jasync/logs/` 笔记标注详细日志状态和诊断格式版本。复现后可以关闭开关。

字段和故障阶段说明见 [S3 诊断指南](https://github.com/guojuntech/obisidian-jasync/blob/0.2.10/docs/S3-DIAGNOSTICS.md)。

验证：70 个单元测试文件 / 857 项测试、18 项原生 Obsidian 检查、ESLint、TypeScript、生产构建及 ZIP 五文件内容校验通过。Android 实机复现仍待验证。
