# JASync 0.2.9

针对 Android 上 `S3 HEAD network request failed [delete/verify-deleted]: Request Failed. IOException Stream closed` 的兼容调整。

0.2.8 日志表明，失败发生在删除后检查探测对象是否消失的 HEAD 请求；清理 DELETE 返回 204。目前没有证据据此判断 AK 缺少删除权限。

- 删除能力探测的最终检查改用 GET，读取同一个随机私有探测对象，绕开已报告异常的 HEAD 请求。
- 仍须收到明确的 HTTP 404 才通过；对象仍存在、权限错误或原生异常均不会被当作删除验证成功。
- 保留 0.2.8 的详细日志、条件写删和恢复机制。普通文件元数据检查仍使用 HEAD。

这次调整已通过模拟故障回归；Android 原生网络层的具体根因及手机上的实际效果仍待复测。

验证：69 个单元测试文件 / 850 项测试、18 项原生 Obsidian 检查、ESLint、TypeScript、生产构建及 ZIP 五文件内容校验通过。

## 更新与复测

BRAT 用户更新 `guojuntech/obisidian-jasync` 到 **0.2.9**，重新启用插件后再次同步。手动更新可使用 `jasync-0.2.9.zip`；保留本机的 `data.json`、`data.local.json`、cache 和 recovery，无需重新配置。

日志中 `delete/verify-deleted` 应显示 **GET / 404**。如果仍失败，请在重启或禁用插件前进入 **设置 → JASync → 排障 → 控制台日志 → 保存到笔记**，从 `jasync/logs/` 导出日志。详见 [S3 诊断指南](https://github.com/guojuntech/obisidian-jasync/blob/0.2.9/docs/S3-DIAGNOSTICS.md)。
